# 0004 — MCP как единый провайдер проектного контекста

Требование Day 31 («через MCP предоставить AI-ассистенту контекст проекта») реализовано не как отдельный артефакт, а как хребет архитектуры: один MCP-сервер обслуживает всех AI-потребителей — OpenCode, Помощник по проекту и автоматический AI Code Review. Помощник (`/help`) — web-интерфейс самого проекта: его backend работает MCP-клиентом собственного MCP-сервера (stdio) и получает тот же контекст, что и OpenCode. Это делает MCP-реальность архитектурной, а не искусственной.

## Consequences

- Все потребители получают контекст через один и тот же набор инструментов — исключается расхождение «что видит OpenCode» и «что видит Помощник».
- Каждый инструмент обязан возвращать ограниченный структурированный результат (отрывки, лимиты строк, агрегаты) — без этого три потребителя размножили бы расход токенов.
