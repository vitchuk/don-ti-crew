# Спецификация: MCP-сервер проектного контекста

Владелец контекста: `Git Context (MCP)` (см. [architecture.md](../../docs/architecture.md)). Статус: черновик.

## Цель

Пакет `services/mcp-server` — MCP-сервер на stdio-транспорте (ADR-0004), единственный провайдер **проектного контекста** для всех **AI-потребителей**: OpenCode, backend Помощника (/help) по проекту и review-CLI. Сервер предоставляет **MCP-инструменты** двух групп: git-контекст текущего репозитория (ветка, статус, diff, список файлов) и поиск по **индексу знаний** (`search_project_docs`, прокси к пакету knowledge — [спека 003](../003-knowledge-rag/)). Все результаты — компактный ограниченный JSON для экономии токенов; какие-либо записи в git и мутации рабочего дерева исключены.

## Сценарии использования

1. **OpenCode.** Разработчик запускает OpenCode в корне репо; MCP-сервер зарегистрирован в `opencode.json` (локальный, stdio), его инструменты доступны AI-агенту наравне со встроенными.
2. **Помощник по проекту.** Backend приложения `apps/assistant` спавнит MCP-сервер как child-процесс, работает MCP-клиентом и получает **проектный контекст** одним вызовом `get_context` (ветка, clean, изменённые файлы, последний коммит) — тот же контекст, что видит OpenCode (ADR-0004).
3. **Review-CLI.** CLI автоматического **AI Code Review** (спека 005) через MCP-клиент получает diff и список изменённых файлов для передачи в LLM.
4. **Поиск по проекту.** AI-потребитель спрашивает «где описана фаза отдыха?» — `search_project_docs` проксирует запрос в пакет knowledge и возвращает top-k находок с файлом и заголовком (сырьё для **Цитаты** в ответах Помощника).
5. **Экономия токенов.** AI-агент запрашивает diff репозитория с 5000 строк изменений — ответ усекается до `maxLines = 400` строк с признаком `truncated`; вывод любого инструмента не превышает разумных лимитов.

## Требования

### Функциональные (FR)

- **FR-1.** Пакет `services/mcp-server` в pnpm-workspace (ADR-0001), TypeScript; MCP SDK — `@modelcontextprotocol/sdk`; транспорт — **только stdio**; запускается потребителями как child-процесс от корня репо. HTTP/SSE-транспорта нет.
- **FR-2.** Сервер предоставляет ровно семь **MCP-инструментов** со следующими точными контрактами (идентичные имена и поля потребляются спеками 004 и 005):
  - `get_current_branch()` → `{ branch: string }`
  - `git_status()` → `{ clean: boolean, changes: [{ file, state }], truncated: boolean }` — не более 200 изменений
  - `git_diff(args { target?: string, base?: string, head?: string, maxLines: number = 400 })` → `{ diff: string, totalLines: number, truncated: boolean }`. Без `base`/`head` — diff рабочего дерева против `target` (по умолчанию HEAD); с `base` и `head` — diff между merge-base(`base`, `head`) и `head` (сценарий «ревью PR», спека 005). Одновременное задание `target` вместе с `base`/`head` — ошибка валидации.
  - `changed_files(args { base: string, head: string })` → `{ files: [{ path, state }], truncated: boolean }` — файлы, изменённые между merge-base(`base`, `head`) и `head`, со статусами `added | modified | deleted | renamed`.
  - `list_files(args { path?: string, limit: number = 500 })` → `{ files: [{ path, bytes }], truncated: boolean }`
  - `get_context()` → `{ branch, clean, changedFiles: [{ file, state }], lastCommit: { sha, message, date }, truncated: boolean }` — комбинированный инструмент: один вызов вместо трёх (`get_current_branch` + `git_status` + последний коммит).
  - `search_project_docs(args { query: string, k: number = 3 (диапазон 1..5), type?: 'readme'|'docs'|'specs'|'adr'|'code'|'config' })` → `{ results: [{ file, heading?, excerpt (≤ 500 символов), score }], total }` — проксирует `query()` пакета knowledge.
  - Все ref-аргументы (`target`, `base`, `head`) валидируются: не начинаются с `-`, не содержат пробелов и не выглядят git-опциями (защита от option-injection, FR-3/NFR-3); в git передаются после разделителя `--`.
- **FR-3.** Git-инструменты работают в текущем рабочем каталоге репо (cwd процесса сервера) и **read-only**: не выполняют commit, checkout, add, push и любые иные мутации git или рабочего дерева.
- **FR-4.** `list_files` уважает `.gitignore` и исключает каталоги `node_modules`, `dist`, `.data`, `.git`.
- **FR-5.** Усечение и экономия токенов: `diff` — не более `maxLines` строк (по умолчанию 400); `list_files` — не более `limit` файлов (по умолчанию 500); `excerpt` — не более 500 символов; текстовые поля результатов несут агрегаты/отрывки, **никогда целые файлы**. Каждый инструмент, применяющий лимит, возвращает поле `truncated: boolean`.
- **FR-6.** `get_context` — комбинированный **MCP-инструмент** (см. FR-2): один вызов возвращает то, что иначе потребители собрали бы тремя вызовами (ADR-0004, экономия токенов).
- **FR-7.** `search_project_docs` проксирует `query()` пакета knowledge (спека 003): передаёт `query` и `type`, ограничивает `k` диапазонами 1..5 по умолчанию 3; `excerpt` не длиннее 500 символов. Если **индекс знаний** не построен — текст ошибки ровно одно предложение: «Индекс знаний не построен — запустите `pnpm rag:index`.» Если Ollama недоступна — одно предложение с подсказкой запустить Ollama на `http://localhost:11434`.
- **FR-8.** Аргументы каждого инструмента валидируются (unknown/некорректные поля — осмысленная ошибка). Ошибки возвращаются как результат инструмента `isError: true` с текстовым сообщением; паника/исключение не роняют процесс и не ломают соединение.
- **FR-9.** Сервер зарегистрирован в OpenCode локально: файл `opencode.json` в корне репо с ключом `mcp`; тип сервера `local`, команда запускает процесс сервера, `cwd` — корень репо (фактический формат сверен с https://opencode.ai/docs/mcp-servers/ — см. plan.md).

### Нефункциональные (NFR)

- **NFR-1.** Экономия токенов: описание каждого **MCP-инструмента** — максимально короткое (≤ 1 предложение); никаких лишних полей в ответах.
- **NFR-2.** Производительность: старт сервера < 2 с; ответ git-инструментов < 1 с на типичном репо; таймаут `search_project_docs` — 30 с (после — ошибка одно предложение).
- **NFR-3.** Безопасность: только чтение (FR-3); аргумент `path` не позволяет выйти за корень репо; используются только `git ls-files/diff/status/rev-parse/log` со строго фиксированными аргументами без прохода через shell.
- **NFR-4.** Зависимости: `@modelcontextprotocol/sdk`, `zod` (валидация аргументов), workspace-зависимость knowledge (см. plan.md — внедрение через интерфейс). Ничего сверх этого без обоснования.
- **NFR-5.** Node 22 LTS + pnpm (версия фиксируется `packageManager`/`engines` в корневом `package.json`; CI — Node 22 LTS, см. спеку 005); кроссплатформа (Windows/Posix): git-вызовы с `-z`/NUL-разделителями, устойчивые к путям и кодировке.

## Вне объёма

- HTTP/SSE-транспорт и публичный сетевой доступ к серверу.
- Любые операции записи в git (коммиты, ветки, stash, cherry-pick) и очистка/перезапись файлов.
- Поддержка нескольких репозиториев (мульти-репо).
- Реализация эмбеддингов, чанкирования и поиска — это пакет knowledge ([спека 003](../003-knowledge-rag/)); mcp-server только проксирует.
- UI, кэширование ответов, другие инструменты помощника (04) и review workflow (05).

## Критерии приёмки

- **AC-1.** Дано: мок-репозиторий с одним коммитом и чистым рабочим деревом. Когда вызван `get_context`. Тогда ответ: `branch` = имя ветки, `clean = true`, `changedFiles = []`, `lastCommit` содержит `sha`, `message`, `date`.
- **AC-2.** Дано: мок-репозиторий с изменённым файлом, добавленным файлом, удалённым файлом и untracked-файлом. Когда вызван `git_status`. Тогда `clean = false`, `changes` содержит все четыре файла с различимыми `state`.
- **AC-3.** Дано: изменённый файл даёт diff в 500 строк. Когда вызван `git_diff` без аргументов. Тогда `totalLines = 500`, `truncated = true`, `diff` содержит ≤ 400 строк.
- **AC-4.** Дано: в мок-репо 600 tracked-файлов, а также каталог `node_modules` и файл в `.data`. Когда вызван `list_files`. Тогда `files` содержит ≤ 500 записей с `path` и `bytes`, `truncated = true`, и не содержит записей из `node_modules`, `dist`, `.data`, `.git`.
- **AC-5.** Дано: подкаталог `docs/` репозитория. Когда вызван `list_files` с `path = 'docs'`. Тогда возвращены только файлы указанного подкаталога и его вложенных подкаталогов.
- **AC-6.** Дано: построен реальный **индекс знаний** (пакет knowledge). Когда вызван `search_project_docs { query: 'фаза отдыха', k = 2 }`. Тогда ответ содержит `results` не длиннее 2 элементов с `file`, `heading` (опционально), `excerpt` ≤ 500 символов и `score`; `total ≥ 2`.
- **AC-7.** Дано: БД **индекса знаний** отсутствует. Когда вызван `search_project_docs`. Тогда получена ошибка с текстом ровно одно предложение, содержащим подсказку запустить `pnpm rag:index`. Процесс сервера продолжает отвечать.
- **AC-8.** Дано: `opencode.json` в корне репо с сервером, зарегистрированным под ключом `mcp`. Когда открыт OpenCode в корне репо (ручная smoke-проверка). Тогда инструменты сервера (`get_context`, `search_project_docs`, …) доступны агенту и возвращают корректные ответы.
- **AC-9.** Дано: набор инструментов сервера. Когда выполняется обзор кода и тестов (review). Тогда ни один инструмент не выполняет git-записи или модификацию файлов; на репо мок-тестов рабочий дерево и HEAD после выполнения инструментов остаются неизменными.
- **AC-10.** Дано: инструмент вызван с некорректными аргументами (например, `k = 10` в `search_project_docs` или несуществующий `path` в `list_files`). Тогда возвращается `isError: true` с осмысленным текстом ошибки; процесс сервера жив и последующие вызовы работают.
- **AC-11.** Дано: мок-репо с ветками `main` и `feature`, в `feature` два коммита поверх `main`. Когда вызван `changed_files { base: 'main', head: 'feature' }` или `git_diff { base: 'main', head: 'feature' }`. Тогда результат содержит только изменения между merge-base и `head` (два коммита), статусы в `changed_files` — added/modified.
- **AC-12.** Дано: вызов `git_diff` с `target = '--output=x'` (или `base`/`head` с ведущим `-`). Тогда получена ошибка валидации (isError), файл `x` не создаётся, git не получил его как опцию (read-only FR-3 не нарушен).
