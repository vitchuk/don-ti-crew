# Спецификация: Помощник по проекту

Владелец контекста: `Assistant Q&A` (см. [architecture.md](../../docs/architecture.md)). Статус: черновик.

## Цель

«Помощник (/help)» — функционал самого проекта: одностраничный web-интерфейс (пакет `apps/assistant`, Vue 3), который запускается локально командой `pnpm assistant:dev` — UI и backend одним dev-сервером. Разработчик задаёт вопрос о проекте репозитория: «как работает таймер?», «какие ADR приняты?», «что изменилось в этой ветке?» — и получает ответ на основе **проектного контекста** и **фрагментов знаний**, с **цитатами** (файл и заголовок). Это не команда и не ассистент OpenCode — `/help` работает сам по себе, без OpenCode (см. ADR-0001, ADR-0004).

## Сценарии использования

1. **Вопрос по продукту.** Разработчик открывает `pnpm assistant:dev` → localhost, печатает «как работает таймер?». Backend собирает контекст через MCP (`get_context`), ищет top-4 **фрагмента знаний** (`knowledge.query`), отдаёт вопрос + отрывки в LLM. Ответ объясняет таймер-движок и ссылается на файлы (например, `specs/001-tabata-timer/spec.md`).
2. **Вопрос по решениям.** «Какие ADR приняты?» — ответ перечисляет ADR с путями к файлам `docs/adr/*.md`.
3. **Вопрос по текущей ветке.** «Что изменилось в этой ветке?» — backend дополнительно запрашивает MCP-инструмент `git_diff(maxLines = 200)`; ответ опирается на diff, а `context.changedFilesCount` отражает число изменённых файлов.
4. **Честный отказ.** Вопрос вне документации («какая погода в Лондоне?») — Помощник отвечает, что не нашёл ответа в документации проекта, и не сочиняет.
5. **Деградация окружения.** Ollama не запущен (или индекса знаний нет, или ключа DeepSeek нет) — UI показывает одну понятную фразу с инструкцией, что сделать (например, «запустите pnpm rag:index»), остальной интерфейс работает.
6. **Локальная история.** Перезагрузил страницу — вопрос-ответ с цитатами восстановился; кнопка «новый вопрос» начинает чат с чистого листа.

## Требования

### Функциональные (FR)

- **FR-1.** Пакет `apps/assistant`: одностраничный web-UI (Vue 3 + TypeScript) и backend (Node, HTTP API) в одном пакете; запускаются целиком командой `pnpm assistant:dev` (UI + backend одним dev-сервером, localhost). Backend-фреймворк — Hono (обоснование в [plan.md](plan.md)).
- **FR-2.** Backend API (контракты и DTO — в [plan.md](plan.md)):
  - `POST /api/ask` с телом `{ question: string }` → `200 { answer, citations, context }`, где `context: { branch, clean, changedFilesCount }`;
  - `GET /api/health` — статус зависимостей (LLM-провайдер, индекс знаний);
  - невалидный вопрос (пустой или длиннее 2000 символов после обрезки пробелов) → `400` с коротким пояснением.
- **FR-3.** Оркестрация ответа (строго в этом порядке):
  1. MCP-клиент (stdio, spawn `services/mcp-server`) — MCP-инструмент `get_context()`; при вопросе об изменениях дополнительно `git_diff(maxLines = 200)` (лимит строк в diff — 200);
  2. `knowledge.query(question, k = 4)` — поиск top-4 фрагментов знаний по **индексу знаний**;
  3. сборка промпта: вопрос + компактный контекст git + отрывки фрагментов; системные правила: отвечать **только** на основе переданного контекста, цитировать пути файлов, при нехватке контекста честно сообщать «не нашёл в документации»;
  4. вызов LLM.
- **FR-4.** Цитаты: `citations` — список файлов (и заголовок, если известен) всех фрагментов знаний, переданных в промпт; в UI отображаются как текстовые пути (не кликабельные ссылки).
- **FR-5.** LLM-провайдер: по умолчанию `deepseek-chat` (OpenAI-совместимый API, ключ из env `DEEPSEEK_API_KEY`); офлайн-фолбэк — локальная модель `qwen3:1.7b` через Ollama; переключение — env `ASSISTANT_LLM=deepseek|ollama`. Ключ хранится и используется **только на backend** — в frontend-бандле его нет; `.env` в `.gitignore` (см. ADR-0005).
- **FR-6.** Ошибки деградации — одна понятная фраза в UI с инструкцией, что сделать. Обязательные случаи: Ollama не запущен (при `ASSISTANT_LLM=ollama`); ключ `DEEPSEEK_API_KEY` не задан (при `ASSISTANT_LLM=deepseek`); индекс знаний отсутствует — «запустите pnpm rag:index»; MCP-сервер недоступен. UI при этом остаётся работоспособным.
- **FR-7.** UI: одностраничный чат — список сообщений (вопрос / ответ / цитаты-пути), поле ввода, кнопка отправки, кнопка «новый вопрос» (очищает чат целиком, включая локальную историю).
- **FR-8.** Локальная история чата хранится в `localStorage` браузера (обоснование в [plan.md](plan.md)) и восстанавливается при перезагрузке страницы. Хранятся только сообщения текущего чата: последние 50 сообщений, более старые отбрасываются.
- **FR-9.** Когда вызывать `git_diff`: детерминированная эвристика по ключевым словам вопроса (`diff`, `изменени*`, `ветк*`, `branch`, `git`, `commit`, `коммит`, `PR`, `merge`; полный regexp — в [plan.md](plan.md)); иначе вызывается только `get_context()`.

### Нефункциональные (NFR)

- **NFR-1.** Полный ответ (без стриминга) обычно ≤ ~15 с: p50 полного времени (от отправки вопроса до отображения ответа) на локальной машине при работе окружении ≤ 15 с.
- **NFR-2.** Экономный промпт: в LLM уходят отрывки фрагментов знаний (не полные файлы) и компактный git-контекст; контролируемый суммарный размер (бюджеты — в [plan.md](plan.md)) — см. ADR-0004 (ограниченные структурированные результаты).
- **NFR-3.** Без авторизации; всё локально: backend слушает localhost; сетевые вызовы наружу — только к выбранному LLM-провайдеру (DeepSeek API или локальная Ollama).
- **NFR-4.** Backend работает как **AI-потребитель** собственного MCP-сервера и получает тот же проектный контекст, что и OpenCode (ADR-0004) — расхождений «что видит OpenCode / что видит Помощник» нет.
- **NFR-5.** Без UI-библиотек компонентов — собственный CSS; без новых зависимостей сверх оправданных в [plan.md](plan.md).

## Вне объёма

- Деплой на public URL / публикация Помощника (работает только локально).
- Стриминг ответов LLM.
- Авторизация и мультипользовательский доступ.
- Редактирование длинных диалогов (правка/удаление отдельных сообщений, ветвление).
- Монетизация.
- Сама MCP-контрактная база — [спека 002](../002-mcp-server/spec.md); фрагменты знаний, индексация и `knowledge.query` — [спека 003](../003-knowledge-rag/spec.md).

## Критерии приёмки

- **AC-1.** Дано: `pnpm assistant:dev` запущен, Ollama работает, `DEEPSEEK_API_KEY` задан (или `ASSISTANT_LLM=ollama`), индекс знаний построен. Когда задал «как работает таймер?». Тогда получен непустой ответ про таймер-движок, `citations` содержит пути к файлам проекта (минимум `specs/001-tabata-timer/spec.md` или исходники таймера), `context.branch` равен текущей ветке репозитория.
- **AC-2.** Дано: те же условия. Когда задал «какие ADR приняты?». Тогда ответ перечисляет принятые ADR с путями `docs/adr/*.md` в цитатах.
- **AC-3.** Дано: в текущей ветке есть изменения относительно main (N файлов), задан вопрос «что изменилось в этой ветке?». Тогда backend вызвал `git_diff(maxLines = 200)`, ответ описывает изменения, `context.changedFilesCount > 0`.
- **AC-4.** Дано: обычные условия. Когда задал вопрос, которого нет в документации проекта («какая погода в Лондоне?»). Тогда ответ содержит честное сообщение вида «не нашёл в документации» и не содержит выдуманных фактов; на несвязный вопрос цитат может не быть.
- **AC-5.** Дано: `ASSISTANT_LLM=ollama`, процесс Ollama остановлен. Когда задал вопрос. Тогда в UI показана одна фраза с инструкцией запустить Ollama; интерфейс (поле ввода, история) работает; `GET /api/health` отражает недоступность LLM.
- **AC-6.** Дано: файл индекса знаний отсутствует (например, после чистого клона). Когда задал вопрос. Тогда в UI показана одна фраза с инструкцией «запустите pnpm rag:index»; попытки LLM-вызова нет.
- **AC-7.** Дано: `ASSISTANT_LLM` не задан (по умолчанию `deepseek`), `DEEPSEEK_API_KEY` отсутствует. Когда задал вопрос. Тогда в UI показана одна фраза с инструкцией задать ключ в `.env` (или переключить `ASSISTANT_LLM=ollama`).
- **AC-8.** Дано: открыт ввод. Когда отправил пустую строку (или строку длиннее 2000 символов). Тогда отправка отклонена с одной фразой-подсказкой; запрос `POST /api/ask` на backend возвращается `400`.
- **AC-9.** Дано: в чате есть вопрос-ответ. Когда перезагрузил страницу. Тогда чат восстановлен из `localStorage` (вопрос, ответ, цитаты). Когда нажал «новый вопрос». Тогда чат пуст, и после перезагрузки он остаётся пустым.
- **AC-10.** Дано: собран frontend-бандл. Когда проверили его содержимое. Тогда строки ключа `DEEPSEEK_API_KEY`/значения ключа в бандле нет; все обращения к LLM-провайдеру идут с backend.
- **AC-11.** Дано: пять типовых вопросов подряд при рабочем окружении. Когда измерили время «отправка → отображение ответа». Тогда медианное время ≤ ~15 с (NFR-1); промпт состоит из отрывков, а не полных файлов (NFR-2); наружные сетевые вызовы за один вопрос — только к выбранному LLM-провайдеру и к Ollama-эмбеддингам для поиска (см. спека 003).
