# Спецификация: Tabata-таймер

Владелец контекста: `Training` (см. [architecture.md](../../docs/architecture.md)). Статус: черновик.

## Цель

Чистое PWA-приложение `apps/client` — Tabata-таймер для **совместной тренировки** родителя и ребёнка, занимающихся рядом, перед одним экраном одного устройства. Приложение ведёт сессию по **протоколу Табаты**: показывает текущую **фазу** и оставшееся время, выдаёт звуковые сигналы, считает **раунды** и **циклы**, сохраняет результат в локальную историю. Работает полностью офлайн, без backend (ADR-0003).

## Сценарии использования

1. **Быстрый старт.** Родитель открывает PWA (установленную «на главный экран»), на главном экране выбирает пресет «Табата 20/10 × 8 раундов», нажимает крупную кнопку старта. Двое перед экраном занимаются: идут подготовка → работа → отдых × 8 **раундов** → завершение; в конце видят результат.
2. **Два цикла.** Родитель выбирает пресет «Табата 20/10 × 8 раундов × 2 цикла»: после 8-го раунда первого цикла наступает отдых между циклами (60 с), затем второй цикл.
3. **Свой шаблон.** Родитель настраивает собственный протокол Табаты (например, работа 30 с, раундов 10), сохраняет его как пользовательский **шаблон тренировки** с именем, в следующий раз запускает его одним выбором.
4. **Пауза.** Во время работы нужно ответить на вопрос — родитель нажимает паузу, отсчёт замирает (звуков нет), затем продолжает с той же фазы и того же оставшегося времени.
5. **Прерывание.** Сессию бросают на середине — она сохраняется в историю со статусом `abandoned` и числом фактически завершённых раундов (`completedRounds`).
6. **История.** После тренировки открывают список последних сессий: дата, имя шаблона, раунды/циклы, статус.
7. **Оффлайн.** Второе занятие, в лесу/зале без сети: приложение открывается и полностью работает офлайн.

## Требования

### Функциональные (FR)

- **FR-1.** Приложение — PWA (Vue 3 + Vite + TypeScript + `vite-plugin-pwa`) в пакете `apps/client`; цели: браузер ПК, Android, iOS — через PWA-установку (ADR-0002). UI — русский; i18n-инфраструктура не входит в объём (позже).
- **FR-2.** Таймер реализует конечный автомат фаз в порядке: **подготовка → (работа → отдых × rounds) → отдых между циклами → следующий цикл → … → завершение**. При `cycles = 1` отдых между циклами не наступает никогда.
- **FR-3.** Ход времени — по меткам времени (`performance.now()` либо `Date.now()`), а не накоплением тиков `setInterval`; позиция в фазе вычисляется как `phaseEndsAt - now`, с учётом накопленных пауз. Дрейф недопустим (см. NFR-1).
- **FR-4.** Управление сессией: старт, пауза, продолжение, сброс (в начало протокола) и прерывание (выход/закрытие без завершения). Прерывание фиксируется при выгрузке страницы (`pagehide`); простое сворачивание/скрытие вкладки сессию **не** завершает — таймер продолжает отсчёт по меткам времени.
- **FR-5.** Параметры протокола Табаты: `prepareSec` (по умолчанию 10), `workSec` (20), `restSec` (10), `rounds` (8), `cycles` (1), `restBetweenCyclesSec` (60; используется только при `cycles > 1`). Валидация: все значения > 0; `rounds` 1..30; `cycles` 1..10.
- **FR-6.** Пресеты (поставляемые пресеты приложения, неизменяемые): минимум «Табата 20/10 × 8 раундов» и «Табата 20/10 × 8 раундов × 2 цикла».
- **FR-7.** Пользовательские шаблоны тренировок: создать, переименовать, удалить; хранение локально в IndexedDB через Dexie (ADR-0003). Удаление шаблона не удаляет историю сессий (в сессиях хранится снимок протокола и имя шаблона).
- **FR-8.** Отображение на экране сессии: текущая фаза (различимая цветом), оставшееся время фазы, номер текущего раунда и цикла, прогресс-индикатор сессии (общий ход раундов/циклов).
- **FR-9.** Звуковые сигналы через Web Audio API (без внешних аудиофайлов):
  - отсчёт 3-2-1 в последние 3 секунды каждой фазы: по низкому бипу на каждую из трёх секунд, один высокий бип — в момент смены фазы;
  - сигнал старта Работы (высокий бип) совпадает с высоким бипом смены на Работу;
  - сигнал старта Отдыха — два средних бипа;
  - три бипа — завершение сессии.
  Допустимо, если при свёрнутой вкладке звук прозвучит с задержкой (браузерные ограничения таймеров) — это не-требование. Также не-требование: промежуточные сигналы пропущенных фаз при «догоняющем» тике после возврата на вкладку.
- **FR-10.** История: список последних сессий — дата, имя шаблона, раунды/циклы (`completedRounds`), статус `completed | abandoned`. Сессия сохраняется при завершении (статус `completed`) и при прерывании (статус `abandoned`); `completedRounds` — сколько раундов фактически прошло.
- **FR-11.** PWA: manifest (name, иконки — installable), service worker с офлайн-кэшем (app shell), учёт safe-area на мобильных.
- **FR-12.** Деплой — статика на GitHub Pages; Vite настроен с корректным base-path.
- **FR-13.** Экран настройки пользовательского шаблона: поля протокола с валидацией FR-5; имя шаблона обязательно непустое.

### Нефункциональные (NFR)

- **NFR-1.** Точность хода времени: дрейф < 50 мс за 30 минут (проверяется unit-тестом с fake timers).
- **NFR-2.** Полностью офлайн после первого открытия (исключая сам деплой); никаких запросов к сети в рантайме; никаких внешних API и backend.
- **NFR-3.** UI читаем с расстояния ≥ 2 м: очень крупная типографика цифр и названия фазы, крупные кнопки, `font-variant-numeric: tabular-nums` для отсчёта.
- **NFR-4.** Одна тёмная, высококонтрастная тема; светлой темы нет.
- **NFR-5.** UI оптимизирован для двоих перед одним экраном: одинаково понятен обоим пользователям, крупные элементы управления достигаемы большим пальцем.
- **NFR-6.** Без UI-библиотек компонентов — только собственный CSS; без новых зависимостей сверх оправданных в plan.md.

## Вне объёма

- TTS (синтез речи), мультитаймеры, аккаунты, синхронизация, библиотека упражнений, аналитика, i18n-инфраструктура, Capacitor/сторы (ADR-0002), второй экран/второе устройство (Remote Multiplayer).

## Критерии приёмки

- **AC-1.** Дано: открыт главный экран. Когда выбрал пресет «Табата 20/10 × 8 раундов» и нажал старт. Тогда отображается фаза «Подготовка» с отсчётом 10 с; далее автоматически «Работа» 20 с → «Отдых» 10 с; это повторяется 8 раз; после 8-го раунда — фаза «Завершение»; в истории появляется сессия `completed` с `completedRounds = 8`.
- **AC-2.** Дано: запущена сессия протокола с `cycles = 2`. Когда завершён 8-й раунд первого цикла. Тогда после отдыха 8-го раунда наступает фаза «Отдых между циклами» на 60 с, затем 1-й раунд 2-го цикла; после 16-го раунда — «Завершение».
- **AC-3.** Дано: запущена сессия протокола с `cycles = 1`. Когда завершён 8-й раунд. Тогда фаза «Отдых между циклами» не наступает никогда — сразу «Завершение».
- **AC-4.** Дано: идёт фаза работы (осталось 12 с), нажали паузу. Через произвольное время нажали продолжить. Тогда отсчёт продолжается с 12 с той же фазы; во время паузы бипы не звучат и время не идёт.
- **AC-5.** Дано: сессия прервана на 3-м раунде (завершен 3-й). Когда открыт экран истории. Тогда сессия есть со статусом `abandoned`, `completedRounds = 3`, датой и именем шаблона.
- **AC-6.** Дано: создан пользовательский шаблон с невалидным протоколом (например, `restSec = 0` или `rounds = 31`). Когда пытались сохранить. Тогда сохранение отклонено с русской подсказкой, какие поля неверны.
- **AC-7.** Дано: шаблон переименован/удалён. Когда открыт список шаблонов и история. Тогда список шаблонов обновлён; сессии истории сохраняют прежнее имя шаблона (снимок) и не исчезают.
- **AC-8.** Дано: последние 3 секунды фазы работы. Тогда звучит по низкому бипу каждую секунду; на смене фазы — высокий бип; при переключении фазы с работы на отдых — сигнал отдыха.
- **AC-9.** Дано: приложение установлено и открыто ранее. Когда оно открыто с включённым авиарежимом. Тогда оно полностью загружается и работает (старт сессии, шаблоны, история), без сетевых запросов.
- **AC-10.** Дано: экран сессии на мобильном с notch. Тогда контент не перекрывается системной областью (safe area учтена); цифры отсчёта читаемы с 2 м (верифицируется ревью макета/контраста).
- **AC-11.** Дано: fake timers прогоняют 30 минут сессии. Тогда расхождение с эталонным расписанием фаз < 50 мс (unit-тест).
- **AC-12.** Дано: сборка развёрнута на GitHub Pages по своему base-path. Когда открыт URL. Тогда PWA загружается, manifest валиден (installable), ресурсов 404 нет.
